# 安心租 RentVerity

基于 Vue 3 + TypeScript 的智能租房平台，用于前端项目实践与面试复盘。

产品、文件夹及 GitHub 仓库英文名为 `RentVerity`；前端 npm 包名为 `rentverity`，服务端为 `rentverity-server`。中文名称继续使用“安心租”。

## 技术栈
- Vue3
- Vite
- TypeScript
- Element Plus
- MySQL
- websocket
- Node.js

## 已有基础功能
- 用户的注册登录
- 房源信息的浏览 / 筛查 / 收藏
- 基于地图找房 / 筛选
- 发布房源
- 用户聊天

## 合同 AI 分析

首页“合同 AI 风险分析”进入独立 `/contract-analysis` 页面。登录后上传单份文字型 PDF，服务端使用 PDF.js 逐页提取文本、调用 DeepSeek 获取 JSON，并通过 Zod 和原文引用校验后展示摘要、风险卡与页码定位。未匹配的原文/页码被移除并明确提示，引用核对不保证模型判断正确。

支持拖拽或按钮选择/替换。取消选择、格式错误或多文件不会清掉已有结果；有效替换会清空旧结果并要求重新授权。预览在本地进行，点击开始后才上传，页面明确显示解析、模型分析/引用核验、完成、失败和停止状态；没有虚构上传百分比，也不提前流式展示未核验的风险。停止、网络失败和临时合同过期均可手动重试，切账号/退出会清理本页文件与结果。

限制：10 MB、40 页、60000 字符；暂不支持扫描件 OCR、加密 PDF、DOC/DOCX。原 PDF 不写入服务端磁盘，页文本与结果仅在按用户隔离的内存会话中保留，15 分钟后过期并定期清理。刷新/离开后不提供历史记录。

模型仅通过服务端调用，需要本项目独立 Key；未配置时明确报错。引用核对不提供法律判断准确率或法律意见。

上传在进入 Multer 内存缓冲前先鉴权和准入：每用户 6 次/分钟、每 IP 30 次/分钟、单用户一个上传/解析、单进程最多 4 个；一分钟上传超时。前后端校验扩展名、MIME、非空/10 MB 和标准 PDF 文件头，服务端继续检查解析、页数与文本量。限制不是病毒扫描或完整进程沙箱，多实例部署还需要网关/共享限流；生产环境不要直接暴露开发服务器。

## 登录与低成本体验优化

收藏、发布、资料、真人聊天使用路由登录守卫，登录成功返回原站内路径。浏览器启动/聚焦/定时检查 JWT 到期时间只用于体验，鉴权仍由服务端验签决定。普通 API、头像上传、合同和 SSE 首包的当前 token 返回 401 时统一清理登录态并提示；迟到旧请求的 401 不会退出新账号，另一标签退出也会同步。未实现 refresh token、服务端完整撤销体系或 HttpOnly Cookie 会话；当前 localStorage token 仍有 XSS 风险。

列表、收藏和 AI 卡片缩略图使用原生图片懒加载/异步解码；不把详情主图一律延迟，也不声称已实现虚拟列表、图片 CDN 或性能提升百分比。

## AI 租房助手与服务端筛选

独立 `/ai-assistant` 页面支持租房问答和自动找房，不再展示编辑/确认筛选卡。DeepSeek 通过受控工具提出条件，后端校验用户原话中的城市、预算和房型后查询 MySQL；城市不明确先追问，其他偏好可不限。模型不生成 SQL 或房源记录，每轮最多一次只读检索。真实卡片显示匹配依据，支持详情及列表/地图跳转；严格条件无结果就如实说明，不自动放宽。合同分析、真人聊天与助手上下文隔离。

房源新增独立 `city`、`house_type` 字段；发布时必填城市/房型，已有库用受保护的增量脚本升级，旧值不能确认时保持 NULL。普通列表与助手共用参数化筛选，列表翻页/刷新保留城市等 URL 条件，支持仅设预算下限。助手按月租升序显示最多六条，地图最多 100 条；地铁距离、通勤、学区等缺少可靠字段时会提示无法精确筛选，不声称已满足或进行房源认证。

正文采用 POST Fetch/ReadableStream 读取 SSE 真流式事件，显示理解/查库/生成状态，支持停止与手动重试、断流识别和旧请求隔离。Markdown 使用 markdown-it（禁原始 HTML）+ DOMPurify 白名单净化，禁远程图片自动加载，限制外链协议。约 40ms 合批当前消息更新，已完成消息缓存解析结果；不是逐 token 重算全部历史，也不是完整的增量 Markdown 语法解析器。

当前会话按用户有界保存到 sessionStorage，不提供后端多会话或长期记忆。取消/失败的消息和未完成条件不进入后续上下文；刷新不缓存旧库存卡片。服务端单用户一个活动请求、每分钟 12 次、全局最多 8 个活动请求（单进程限制）；有超时、心跳和背压处理，不提供自动续传/付费重试，不等于生产级分布式限流或完整提示词注入防护。

## 地图 / 列表 / URL 联动

沿用百度 JavaScript WebGL 交互地图（不是静态图片地图）。拖动或缩放结束 300ms 后，把 BD-09 视野边界与筛选条件一起交给服务端查询；URL 保存条件、bounds、中心、缩放和选中房源。刷新、浏览器前进/后退及列表/地图切换可恢复状态。地图卡片定位标点，标点选择高亮对应卡片；普通列表也可定位到地图。

新操作会取消旧请求，并用请求版本阻止迟到响应覆盖；查询结果不会自动重新取景，避免视野跳回和查询循环。离开页面会移除事件、定时器及标记并销毁地图。SDK 加载/初始化失败可回退列表，视野列表可取消范围限制。

地图最多加载前 100 套，不做聚合；范围查询不计无坐标记录。旧迁移 `004` 的散开坐标仅用于演示，不是经过核实的房源地址；新发布通过百度地理编码获取坐标，仍需人工核实。当前视野不支持跨日期变更线。原有 GL SDK 已完成本机真实底图/移动检查，暂不为面试用途迁移新地图引擎。

## 本地开发

使用 Node.js 22.13+，在包含本 README 与 `package.json` 的源码根目录运行：

```powershell
npm install
npm run dev
```

另开终端运行服务端：

```powershell
cd server
npm install
npm run dev
```

服务端配置优先级为显式进程环境 → `server/.env.local` → `server/.env`。在本地覆盖文件填写 `AI_API_KEY`，不与另一项目混用，修改后重启服务端；配置示例和接口见 [服务端说明](server/README.md)。`JWT_SECRET` 必须配置，不再使用固定默认密钥。

前端 API 默认地址为 `http://localhost:3001`，可通过 `VITE_API_BASE_URL` 覆盖。新环境快照/初始化/演示 seed，以及已有库城市/房型增量升级步骤见 [数据库说明](server/database/README.md)。新快照包含当前城市/房型字段，不重复运行旧迁移；已有环境不要重建库。

发布租金、坐标、图片地址和联系方式等由服务端校验，归属只取登录身份。房源不提供风险评分，旧 risk_level 仅为兼容历史表保留，不再作为默认“低风险”展示。聊天室是独立真人会话，支持基础消息持久化、未读/已读与手动重连，不声称具备自动重连、可靠重投或完整即时通信能力。

聊天室每页 50 条，按 beforeId 加载更早历史、保留滚动锚点，当前最多展示 500 条；重新选择会话回到最近记录。HTTP 历史与实时消息按持久化 ID 合并去重/排序，手动重连重新同步最近记录，当前页草稿保留但不自动补发。可见且滚动到底部时，仅确认已展示到的游标；不是逐条对端已读回执。服务端单连接最多 32 个排队任务串行处理，超限明确拒绝；不保证跨连接/跨节点全局顺序，也不提供 ACK/客户端消息幂等重投。

发布提交锁在异步校验前生效，校验后保存参数快照；地理编码等待期间离开/换账号不会继续发旧意图，请求完成后也不做迟到跳转。这只能防当前页并发提交，不是后端跨标签/超时重试幂等，也不能撤销已经入库的发布。

## 验证命令

- 源码根：`npm run build`。
- 源码根：`npm run test:chat`（3 项聊天合并/上限/字段映射纯函数检查，不调用外部服务）。
- `server/`：`npm test`（构建、PDF/证据、筛选/助手/接口与本地模型协议测试，不调用真实 DeepSeek 或业务数据库）。
- `server/`：`npm audit --omit=dev --registry=https://registry.npmjs.org`（生产依赖已知漏洞检查；镜像不一定提供 audit，不修改全局配置，也不等同于完整安全审计）。本轮生产报告 0 项，全量仍有 5 项开发工具链告警，暂未替换 ts-node-dev。
- `server/`：`npm run smoke:contract`（显式调用真实模型一次，仅发送合成合同，不使用私人文件）。
- `server/`：`npm run smoke:assistant`（显式多次调用真实模型并只读查当前数据库，逐次报告工具/流式阶段；次数随匹配分支变化，固定场景不代表准确率）。
- `server/`：`npm run smoke:business`（创建/清理独立临时 MySQL 测试库，测试完整基础业务；不写现有业务库或调用模型；权限不足时可显式提供空测试库，见数据库说明）。
- 源码根：`npm run check:sensitive`（提交前检查被跟踪的环境文件/上传文件/私钥路径，不读取秘密、不操作 Git 索引）。

开发记录与真实模型验收状态统一保存在外层 `开发记录.md`，下一步见实施路线。PDF worker 与字体/CMap 资源随构建本地提供，不依赖浏览器向第三方 CDN 获取合同解析资源。

## 重命名与数据兼容

- 文件夹和 GitHub 仓库的重命名由用户操作，步骤保存在外层 `RentVerity-改名步骤.md`。
- 现有数据库连接继续使用 `.env` 的 `DB_NAME`；品牌改名不直接搬迁或删除已有数据库。新建环境建议库名 `rentverity`。
- SQL 迁移不再硬编码数据库名，执行前必须选中与 `DB_NAME` 一致的目标数据库；例如新库使用 `mysql --database=rentverity` 连接后执行迁移。
- 登录缓存键已改为 `rentverity_current_user`，升级后需重新登录；账号、房源和聊天记录不受影响。
- Git 历史、尚未手动更名的路径和既有数据库标识可保留历史名称，不能仅替换连接配置而不迁移数据。
