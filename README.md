# 安心租 RentVerity

基于 Vue 3 + TypeScript 的智能租房平台，用于前端项目实践与面试复盘。

产品、文件夹及 GitHub 仓库英文名为 `RentVerity`；前端 npm 包名为 `rentverity`，服务端为 `rentverity-server`。中文名称继续使用“安心租”。

## 技术栈
- Vue3
- Vite
- TypeScript
- Element Plus
- MySQL
- websocket
- Node.js

## 已有基础功能
- 用户的注册登录
- 房源信息的浏览 / 筛查 / 收藏
- 基于地图找房 / 筛选
- 发布房源
- 用户聊天

## 合同 AI 分析

独立 `/contract-analysis` 页面支持文字型 PDF。选择文件只检查本地文件头，点击“开始分析”并确认授权后才上传；预览需单独打开，通过 File.slice 范围读取，由 PDF.js worker 渲染有界 canvas，点击风险项定位原页。刷新需重新选文件，不持久化浏览器文件或合同历史。

默认边界为 **100MiB（104857600字节）、300页、提取文本600000字符、64块**，这些条件必须同时满足。主服务通过 Busboy 流式写入私有临时目录，鉴权、来源、限流、账号活动任务互斥和磁盘空间预留先于接收；实际字节及 multipart 完整结束通过后，才由可终止的独立 PDF.js 子进程解析。原文件和有界解析中间产物不进入公开 uploads，解析后尽早回收；失败/取消主动清理，TTL、30秒清扫和启动遗留清理兜底。

按段落、条款与字符预算切块，保留原页码、提取文本位置、相邻重叠和有限共享上下文；超长单页继续拆分。单次输入最多16000字符（不是精确token计数）、单合同最多96次模型调用；模型块分析全局并发2，单块有限自动重试一次，另支持一次仅重试未完成块。成功块不会自动重跑，部分失败明确展示“非全文分析成功”。每块经严格结构、页码和原文核验后，由服务端去重排序，**最终最多20条**，不拼接全文再次调用模型、不要求凑满。

任务上传默认3分钟、总生命周期12分钟、终态保留15分钟；前端上传后轻量轮询，支持停止、网络恢复后继续查看。切账号/退出清除当前页文件与结果。模型只通过服务端调用本项目独立 DeepSeek Key，停止不能保证上游未计费；安全日志只记录标识、状态、大小、耗时和错误码，不记录合同正文。

暂不支持扫描件OCR、加密PDF、图片或DOC/DOCX、断点续传。独立进程采用最小环境、V8堆和输出/时间/并发限制，**不是完整安全沙箱或病毒查杀**，不限制所有原生内存/RSS；引用存在也不代表风险判断正确。配额及互斥为单实例实现。配置、接口及复现见 [服务端说明](server/README.md) 和 [本轮验收报告](docs/contract-large-reliability-2026-11-02.md)。

## 登录与会话

登录凭证为单个 JWT，由服务端写入 `rentverity_session` HttpOnly Cookie：有效期 7 天、`SameSite=Lax`、`Path=/`、不设置 Domain。本项目只在本地 HTTP 运行，因此 `Secure=false`。登录和注册的 JSON 不再返回 token，前端不读取 JWT、不写入 localStorage/sessionStorage，也不在 WebSocket URL 传递凭证。升级会清理旧 `rentverity_current_user` 缓存，需重新登录；注册成功后直接登录，可选头像随后通过 Cookie 上传。

用户资料、非凭证的 `sessionId` 和 `expiresAt` 只存在 Vue ref 内存中。刷新后先通过 `GET /users/me` 恢复身份，再决定私有路由是否放行；聚焦/定时检查只重新核对登录状态，不续签 JWT。普通 API、头像、合同和 SSE Fetch 均使用 `credentials: 'include'`。退出需服务端确认清除 Cookie，失败时保留当前状态。localStorage 只发送不含身份或凭证的随机变化通知，其他同源标签收到后清空私有页面并向后端重新核对；助手对话的 sessionStorage 仍按用户隔离保留。

前端用会话版本隔离旧响应，用不具备认证能力的 `X-RentVerity-Session` 与 Cookie 中的会话 ID 比对，防止共享 Cookie 换账号后发送旧意图。同源标签在支持 Web Locks 时串行执行登录/注册/退出及身份更新，不支持时仅保证当前标签串行；认证期间旧聚焦检查和迟到 401 不更新身份。没有自动续期、refresh token 或 JWT 撤销名单；退出清除当前浏览器 Cookie 并关闭对应的现有聊天连接，不代表已签发 JWT 在服务端立即作废。

轻量 CSRF 防护为 `SameSite=Lax` 配合写操作的精确 Origin 白名单校验，缺失 Origin 时才回退 Referer，两者都缺失则拒绝。校验在 JSON 解析和上传缓冲前执行，覆盖登录、注册、退出、发布、收藏、头像、合同和助手请求；WebSocket 握手单独要求可信 Origin。CORS 允许凭证且只允许明确来源，不使用 `*`。HttpOnly 限制脚本直接读取 Cookie，仍需现有的文本转义/Markdown 净化；不能据此宣称消除 XSS 或实现完整安全体系。协议、错误码与配置见 [服务端说明](server/README.md)。

列表、收藏和 AI 卡片缩略图使用原生图片懒加载/异步解码；不把详情主图一律延迟，也不声称已实现虚拟列表、图片 CDN 或性能提升百分比。

## AI 租房助手与服务端筛选

独立 `/ai-assistant` 页面支持租房问答和自动找房，不再展示编辑/确认筛选卡。DeepSeek 通过受控工具提出条件，后端校验用户原话中的城市、预算和房型后查询 MySQL；城市不明确先追问，其他偏好可不限。模型不生成 SQL 或房源记录，每轮最多一次只读检索。真实卡片显示匹配依据，支持详情及列表/地图跳转；严格条件无结果就如实说明，不自动放宽。合同分析、真人聊天与助手上下文隔离。

房源新增独立 `city`、`house_type` 字段；发布时必填城市/房型，已有库用受保护的增量脚本升级，旧值不能确认时保持 NULL。普通列表与助手共用参数化筛选，列表翻页/刷新保留城市等 URL 条件，支持仅设预算下限。助手按月租升序显示最多六条，地图最多 100 条；地铁距离、通勤、学区等缺少可靠字段时会提示无法精确筛选，不声称已满足或进行房源认证。

正文采用 POST Fetch/ReadableStream 读取 SSE 真流式事件。服务端执行器分别记录查询/说明状态及 requestId/callId，查询成功才发送真实卡片；查询成功但说明失败/停止时保留卡片与已确认条件，半截说明不进后续上下文。前端核对事件顺序、标识、条件与结果，检索轮没有对应结果（空数组也算结果）就不能完成。Markdown 使用 markdown-it（禁原始 HTML）+ DOMPurify 白名单净化，禁远程图片，模型生成的所有链接均显示为纯文本，详情跳转只由真实卡片按钮创建。约 40ms 合批当前消息更新、缓存未变消息，仍是有界整段解析。

执行前仅允许一次漏调用/JSON/参数类型纠错，未知工具和越权参数直接拒绝；明确城市、月租、房型与用户证据不一致或表达不确定时澄清，网络/查询/说明失败不自动重试。同一请求最多一次只读检索，不承诺跨请求 exactly-once。查询已成功的用户条件可保留；未执行条件及失败/取消正文排除出上下文，刷新不缓存库存卡片。当前会话仅按用户有界保存在 sessionStorage；单用户一个活动请求、每分钟 12 次、全局最多 8 个（单进程），有超时/心跳/背压，未实现自动续传、分布式限流或完整提示词注入防护。

## 地图 / 列表 / URL 联动

沿用百度 JavaScript WebGL 交互地图（不是静态图片地图）。拖动或缩放结束 300ms 后，把 BD-09 视野边界与筛选条件一起交给服务端查询；URL 保存条件、bounds、中心、缩放和选中房源。刷新、浏览器前进/后退及列表/地图切换可恢复状态。地图卡片定位标点，标点选择高亮对应卡片；普通列表也可定位到地图。

新操作会取消旧请求，并用请求版本阻止迟到响应覆盖；查询结果不会自动重新取景，避免视野跳回和查询循环。离开页面会移除事件、定时器及标记并销毁地图。SDK 加载/初始化失败可回退列表，视野列表可取消范围限制。

地图最多加载前 100 套，不做聚合；范围查询不计无坐标记录。旧迁移 `004` 的散开坐标仅用于演示，不是经过核实的房源地址；新发布通过百度地理编码获取坐标，仍需人工核实。当前视野不支持跨日期变更线。原有 GL SDK 已完成本机真实底图/移动检查，暂不为面试用途迁移新地图引擎。

## 本地开发

使用 Node.js 22.13+，在包含本 README 与 `package.json` 的源码根目录运行：

```powershell
npm install
npm run dev
```

另开终端运行服务端：

```powershell
cd server
npm install
npm run dev
```

服务端配置优先级为显式进程环境 → `server/.env.local` → `server/.env`。在本地覆盖文件填写 `AI_API_KEY`，不与另一项目混用，修改后重启服务端；配置示例和接口见 [服务端说明](server/README.md)。`JWT_SECRET` 必须配置，不再使用固定默认密钥。

浏览器用 localhost 打开前端时，API 默认访问 `http://localhost:3001`；用 127.0.0.1 打开时默认访问 `http://127.0.0.1:3001`，可通过 `VITE_API_BASE_URL` 覆盖。Cookie 依赖主机，请保持前后端一致使用 localhost 或 127.0.0.1。服务端默认信任这两个主机的 5173（开发）和 4173（预览）端口；若 Vite 因占用改用其他端口，在 `server/.env.local` 设置完整的 `CORS_ORIGINS` 后重启服务端，不能只改前端地址。新环境快照/初始化/演示 seed，以及已有库城市/房型增量升级步骤见 [数据库说明](server/database/README.md)。本次鉴权迁移不改数据库结构。

发布租金、坐标、图片地址和联系方式等由服务端校验，归属只取登录身份。房源不提供风险评分，旧 risk_level 仅为兼容历史表保留，不再作为默认“低风险”展示。聊天室是独立真人会话，支持基础消息持久化、未读/已读与手动重连，不声称具备自动重连、可靠重投或完整即时通信能力。

聊天室每页 50 条，按 beforeId 加载更早历史、保留滚动锚点，当前最多展示 500 条；重新选择会话回到最近记录。HTTP 历史与实时消息按持久化 ID 合并去重/排序，手动重连重新同步最近记录，当前页草稿保留但不自动补发。可见且滚动到底部时，仅确认已展示到的游标；不是逐条对端已读回执。服务端单连接最多 32 个排队任务串行处理，超限明确拒绝；不保证跨连接/跨节点全局顺序，也不提供 ACK/客户端消息幂等重投。

发布提交锁在异步校验前生效，校验后保存参数快照；地理编码等待期间离开/换账号不会继续发旧意图，请求完成后也不做迟到跳转。这只能防当前页并发提交，不是后端跨标签/超时重试幂等，也不能撤销已经入库的发布。

## 重命名与数据兼容

- 文件夹和 GitHub 仓库的重命名由用户操作，步骤保存在外层 `RentVerity-改名步骤.md`。
- 现有数据库连接继续使用 `.env` 的 `DB_NAME`；品牌改名不直接搬迁或删除已有数据库。新建环境建议库名 `rentverity`。
- SQL 迁移不再硬编码数据库名，执行前必须选中与 `DB_NAME` 一致的目标数据库；例如新库使用 `mysql --database=rentverity` 连接后执行迁移。
- 旧 `rentverity_current_user` 登录缓存已停用并自动删除；JWT 改为 HttpOnly Cookie，账号、房源和聊天记录不受影响。
- Git 历史、尚未手动更名的路径和既有数据库标识可保留历史名称，不能仅替换连接配置而不迁移数据。
