# 合同大文件、分块分析与文件安全验收

日期：2026-11-02；起点：`81d8f44`；Node.js v22.20.0，Windows/Edge，本机单实例。未代为提交或推送，不写业务数据库，不改飞书或原简历。开工时已有的 `docs/assistant-reliability-2026-11-02.md` 修改原样保留；FC执行器、SSE状态机和安全Markdown未改。

## 1. 交付与实际边界

本轮已贯通流式接收→私有临时文件→独立解析→有界分块→真实模型→逐块证据核验→本地去重合并→页面展示，无需拆第二轮。旧内存会话与全文一次模型分析入口移除，旧parse/analyze接口返回410。

| 项目 | 默认边界及行为 |
| --- | --- |
| 文件 | 100MiB=104857600字节，文字型PDF，单file字段；大小、类型、标准文件头、实际解析均校验 |
| 内容 | 300页、600000个提取文本UTF-16字符、64块，所有条件同时满足；不是任意PDF必然解析成功 |
| 单块 | 原文约10000字符、相邻重叠500、共享上下文1200、最多24段；段落/条款优先，长单页继续切分 |
| 输入/输出 | 完整序列化消息content合计≤16000字符，包含提示词/共享上下文/JSON转义；输出预留3600token；字符预算不是精确token计数 |
| 模型预算 | 每合同最多96次实际API尝试、全局并发2；每块最多自动重试一次可重试错误，另一次手动只重试失败块 |
| 结果 | 单块≤6项，经结构/本块连续原文/原始页码校验；服务端精确去重、排序后整份≤20项，不要求凑满 |
| 接收准入 | Cookie/来源/会话标识校验；每账号6次/IP30次每分钟，账号1个活动任务，全局4个；每账号2份/全局64份临时记录 |
| 空间 | 单实例512MiB逻辑配额，磁盘另留256MiB；先预留原文件+12MiB中间输出+1MiB余量，再读取请求体 |
| 解析 | 独立可终止子进程，90秒、并发2、384MiB V8 old-space、12MiB解析输出、16KiB stdout/stderr |
| 生命周期 | 上传3分钟，总任务12分钟且不超过原JWT到期；终态保留15分钟，每30秒清扫，启动清理遗留 |
| 页面 | 选择只读16字节文件头；点击分析才上传；上传后轮询状态；预览单独打开，默认64KiB范围读取，关闭释放worker/canvas |

确定性真实HTTP/隔离解析链路已验证**同一合法PDF同时达到100MiB、300页、600000字符**，模型部分为显式桩。301页或600001字符在模型调用前拒绝。真实模型另测100MiB短文本、53.93万字符长文本等，不能把桩的联合边界说成整份真实模型联合边界。

原文件和`.part`通过原子改名共用预留空间，解析输出同理；不同时复制两份原文件。空间不足507，实际字节不符/接收中断/multipart未结束均不解析。私有目录不在uploads，不使用客户端文件名作路径。配额是逻辑预留，其他进程仍可能抢占磁盘，不是OS磁盘预分配保证；写失败仍清理并记录错误。

解析成功后尽早删除原文件和解析产物，只保留后续分析所需有界文本。成功终态清空块原文缓存；部分失败为重试保留必要文本直到TTL。取消/失败/完成重复清理，删除失败保留配额和cleanupPending，后续清扫重试。停服立即启动任务回收，不等WebSocket/页面关闭；解析进程另有独立守护线程检查父PID和截止，即使解析主线程忙循环，父进程死亡或硬截止也终止，正常由父服务90秒杀进程，孤儿兜底为解析时限+1秒、约200ms检查间隔；不是实时系统硬时限保证。

## 2. 关键实现与协议

| 入口 | 作用 |
| --- | --- |
| `server/src/contracts/limits.ts`、`.env.example` | 配置化、有限范围和公开limits；提高配置上限不代表已验证更大容量 |
| `tempStorage.ts` / `receivePdf.ts` | 私有目录锁、串行空间预留、流式落盘、实际字节及multipart完整性、幂等清理 |
| `isolatedParser.ts` / `parserWorker.ts` / `parserGuard.ts` | 可终止PDF.js进程、最小环境、父进程及独立守护、并发/时间/输出限制 |
| `chunks.ts` / `analysis.ts` | 段落/预算切分、UTF-16位置、重叠/上下文、JSON转义自适应缩块、证据核验、最多20项 |
| `tasks.ts` / `routes/contracts.ts` | 准入、归属、状态、账号互斥、全局模型并发、预算/重试/截止、审计/清扫 |
| `src/services/contracts.ts` / `ContractAnalysis.vue` | 上传/轮询/恢复查看/取消、部分结果、仅失败块手动重试、身份切换清理 |
| `ContractPdfPreview.vue` | 用户主动开启范围预览、原页定位、有界canvas、关闭释放资源 |

接口：`GET /contracts/limits`；`POST /contracts/tasks`（FormData file，`X-Contract-Task-Id`小写UUID、`X-Contract-File-Size`字节）；`GET /contracts/tasks/:id`；`POST /contracts/tasks/:id/retry`；`DELETE /contracts/tasks/:id`。写请求另需可信Origin和匹配的`X-RentVerity-Session`。任务ID不是身份凭证，后端核对用户归属，状态/结果不缓存。

状态为receiving→queued/parsing→analyzing→completed/partial/failed/cancelled。所有块成功才completed；失败块有限重试后仍未完成则partial或failed，成功块不自动重跑。手动补偿只允许一次，仍受原96次预算和创建起12分钟限制，不重置JWT截止。原文件只在解析子进程读入完整Buffer；主服务仅持有流的有界缓冲和受限解析JSON/文本块。

提取页文本先NFC规范化，sources的start/end是该文本的UTF-16位置，不是PDF字节、屏幕坐标或OCR框。引用必须来自本块同一页连续原文，仅忽略空白/NFC等价；共享上下文不能独立作为引用证据。跨页条款可结合邻页理解，quote仍只能取其中一页连续文本。按规范化“类别+引用”精确去重，严重程度/页码/位置排序，最多20；不保证不同措辞的类别/引用语义去重。摘要只拼合有限块摘要，未把全文重新发模型作大请求。

审计只记录任务/块标识、状态、尝试、字节/页/字符/块/API次数、耗时/主进程RSS与错误码，不记录合同正文、文件名、用户身份或上游原文。测试报告中的合成合同输出是显式测试证据，与生产日志策略分开。

## 7. 复现方法

先配置现有MySQL、测试账号及本项目DeepSeek Key于被忽略的server/.env.local，不在聊天/日志写密码。测试默认读取外层本机账号记录，其他环境显式设置RENTVERITY_TEST_USER与RENTVERITY_TEST_PASSWORD；测试不需要用户真实合同、不执行迁移/创建用户。

源码根运行：

```powershell
npm run build
npm run test:assistant
npm run test:session
npm run test:chat
```

server目录运行（真实模型命令会产生费用）：

```powershell
npm test
npm run smoke:contract
npm run smoke:contract-long
npm run smoke:contract-long -- --cases=R09,R12,R13,R17,R32,R35
```

完整脚本现在包含R01—R35，产生35个独立任务，至少30个成功才通过；本次40个记录由首30+中文4+追加5+R35组成，不能用一个合同57个块凑轮数。只重新测试部分用例时保留原始失败记录，不把首次尝试计数抹掉。

浏览器：先构建两端，保持3001/4173空闲，准备Edge及Playwright；可设RENTVERITY_PLAYWRIGHT_PATH指向本机Playwright模块、RENTVERITY_BROWSER_CHANNEL默认msedge。在源码根运行`npm run test:contract:ui`，会自动启动测试服务和预览、生成包括100MiB在内的样本并清理文件，不复用正在运行的生产服务。可重放12类合同操作及真实模型/既有业务回归；外部SDK波动会保留失败记录。

内存：`server/.private/baseline-81d8f44`为本机开工前dist内容快照，未提交且不含.env或密钥。新环境先在单独目录/隔离worktree构建81d8f44，将其dist内容放入该私有目录（不要覆盖当前源码、不要复制.env），再在server运行`npm run smoke:contract-memory`。脚本核对旧限制，再按相同文件8样本输出，不需要人为构造大文件基线。原始JSON和测试日志在源码根.codex_tmp，生成的PDF样本由脚本创建，不要求人工提供。

手动预览：两终端分别在源码根`npm run dev`、server`npm run dev`；打开同主机localhost或127.0.0.1的前端，登录→合同分析→选择PDF（未上传）→授权→分析→观察块进度→点击引用开预览→清除。停止会发DELETE并取消本地请求；刷新后重新选择。网络失败可继续查看原任务或在预算内仅重试失败块。

## 8. 剩余限制与简历表述

- 仅文字型PDF；无OCR、图片/DOC/DOCX、浏览器持久文件、分片上传/续传、长期历史或分布式设施。重启时清除遗留，任务内存记录丢失需重传；实例间无共享互斥/配额。
- 子进程及最小环境不等于安全沙箱：仍以同一OS账号运行；384MiB是V8 old-space，不是RSS/原生解码内存硬限。无病毒查杀/内容消毒，不证明全部恶意PDF都可安全处理。
- 系统级磁盘和所有子进程总RSS未做硬配额。检查空闲空间后外部进程仍可抢占，仍可能写入失败；清理若因权限/占用持续失败，保留配额并拒绝新任务，需修复本机文件系统状态。
- 段落切分、500字符重叠和1200字符共享背景不保证发现远距离条款矛盾；摘要不是全文法律归纳。准确率没有标注集/人工法律评测，不能把引用核验通过率等同风险判断正确率。
- 去重是规范化类别+引用精确匹配，非语义去重；相近措辞可能重复、相同引用也可能代表不同类别。最终只展示排序后的20条，可能存在其他未展示项，不能要求模型凑数。
- 取消不保证上游未计费；页面DELETE失败由服务端截止/TTL兜底。没有集中JWT撤销；已有Cookie有效时服务端不凭本地页面关闭判失效。
- 地图快速切页的百度SDK异常单列于上节，不混为合同错误或宣称已经修复；稳定加载的地图/列表、FC与聊天连接回归通过。

第四条简历建议（仅提供表述，未改原PDF）：

> 实现基于PDF.js与DeepSeek的长合同风险分析，支持100MiB PDF流式上传，结合私有临时目录配额、可终止子进程解析与有界并发分块分析，通过原文/页码校验、失败块重试和服务端去重，输出最多20条可追溯风险提示。

不要将“独立解析进程”写成完整沙箱，“字符预算”写成精确token计数，“位置索引”写成RAG，“主进程采样峰值变化”写成整体系统内存或性能提升百分比。
